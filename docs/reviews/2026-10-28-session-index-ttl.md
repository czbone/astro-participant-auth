# セッション索引の寿命（2026-10-28）

**日付**: 2026-10-28  
**対象**: 認証サーバー [czbone/astro-user-webauthn2](https://github.com/czbone/astro-user-webauthn2) の `sess:user:{userId}`  
**方法**: 認証サーバーの確定資料・実装と、このパッケージのセッション延長を突き合わせた静的確認  
**変更**: この記録では実装を変えていない

このファイルは調査記録です。確定仕様ではありません。

## 結論

全失効が参加アプリのセッションに届かなくなる原因は、認証サーバーがユーザー索引に付けている TTL です。直す場所は認証サーバーです。

参加アプリは、仕様どおり索引を `EXPIRE` しません。索引の寿命をこのパッケージで延ばすには、参加アプリの仕様と Redis の ACL を変える必要があります。

## 何が起きるか

認証サーバーはセッション作成時に、索引 `sess:user:{userId}` へ `SESSION_MAX_AGE_SECONDS`（既定 30 日）を付けます。この TTL を延ばすのは、認証サーバー自身のセッションを検証したときと、新しいセッションを作ったときです。引き渡しで参加アプリのセッションを作ったときも、作成処理が索引の TTL をその時点からやり直します。

参加アプリが入場のたびに延ばすのは、自分の `sess:{APP_ID}:{tokenHash}` だけです。索引は延ばしません。

認証サーバーを開かず参加アプリだけを使い続けると、索引は最後に認証サーバーが TTL を付けた時点から 30 日で消えます。参加アプリのセッション本体は、直前の入場で延ばされているので残ります。スライディングに上限はないので、TTL を 30 日より長くしても、参加アプリを使い続ければ同じずれが起きます。

索引が空になると、全失効は `SMEMBERS` の結果だけを消します。残っている参加アプリのセッションキーは辿れません。

| 操作 | 索引が消えたあと |
| --- | --- |
| 参加アプリのログアウト | 今のブラウザのセッションは消える。別ブラウザや別の参加アプリのセッションは残る |
| メールアドレス変更の確定 | 認証サーバーの `revokeAllForUser` が索引を消すだけで、残った参加アプリのセッションでは入場し続けられる。パスキーは削除されない |
| パスワード再設定の完了 | 全パスキーが削除される。参加アプリの次のリクエストはパスキー 0 件として入場しない |
| アカウント無効化 | 参加アプリの次のリクエストが `disabledAt` を見て、そのリクエストのセッションを未認証にする |

ログアウトが今のセッションだけ消せるのは、このパッケージが索引の要素に加えて、今読んでいる `sess:{APP_ID}:{tokenHash}` も `DEL` するためです。認証サーバーの `revokeAllForUser` は、索引が空ならそこで戻ります。

## 根拠

認証サーバーの [Redis](https://github.com/czbone/astro-user-webauthn2/blob/main/docs/redis.md) は、`sess:user:{userId}` の TTL を「本体に合わせて維持」とし、全失効を `SMEMBERS` から各セッションキーの `DEL` としています。

実装は `src/server/db/session.ts` です。

- `create` がセッション本体を `SET ... EX ttl` し、索引へ `SADD` したあと `EXPIRE` する
- `touch` が認証サーバーのセッション本体と索引の両方を `EXPIRE` する
- `revokeAllForUser` が `SMEMBERS` の結果を消し、要素が無ければ索引を `DEL` して戻る

参加アプリ側の契約は、索引の `EXPIRE` をしないことです。入場時の延長は `src/server/auth/access.ts` の `slideSession` で、対象は自分のセッションキーだけです。Redis ACL の `sess:user:*` に書かれているコマンドは `SREM`、`SMEMBERS`、`DEL` です（`src/server/auth/participant-redis-user.ts`）。

## 認証サーバーでの直し方

索引をセッション TTL では消さない。削除は全失効の `DEL` に任せ、セッション本体が残っているあいだ索引も残します。

参加アプリの `slideSession` から索引を `EXPIRE` する直し方は、このパッケージ単独では契約に合いません。索引の `EXPIRE` を参加アプリへ許す仕様と ACL の変更が先です。
